### Result

The contract is pinned to the bead's literal **20 operations**, with strict
arguments, contextual typed replies, all 17 listed event names and all 16 error
codes. There are no log/statistics endpoints or log topic in this change.
The explicitly required LogEntry object stays typed; populated and omitted hash
examples are in diagnostic Error.details entries, checked as LogEntry values by
the fixture coverage test.

app.info contains every hello field: proto, server, engine, instance,
engine_epoch, state, caps, limits and policy, then uptime_s, upgrade_pending,
clients and subscriptions. Removing any of the four previously missing fields
fails contextual decoding.

The six NDJSON files contain **187 records**: 65 requests, 111 server frames,
five expected models and six volatile declarations. Literal coverage obligations
require every optional Torrent field both present and absent in Torrent and
TorrentDetail examples. They also enumerate the optional detail, Playable, File,
Summary, SummaryDaemon, SummaryNetwork, TopTorrent, Limits, NetworkState,
Settings and LogEntry fields. Complete and minimal Playable objects are included.
All ten torrent states occur. Inactive/error examples carry their reasons;
metadata/parked progress, pre-metadata size, non-live rates/peers and zero-
download ratio are omitted. Non-empty delta added and removed frames are present.

PendingResult has a required MutationRef. AddResult and RemoveResult flatten a
MutationResult enum: Done, or Pending with a required ref. Upload-limit results
use that same enum. Invalid pending replies cannot deserialize without a valid
ref; the round-trip path uses contextual Reply::decode and exercises all five
pending-capable operations with positive and negative cases.

`api::validation` owns reusable bounds and revision checks. Request
deserialization invokes it, as do Reply::decode, Event::validate and fixture
checks. Rules cover non-empty/max topic and hash lists, numeric upload minimum
16384 and the u64 range, omitted/null/numeric update semantics, progress 0..=1
for Torrent/File/TopTorrent (including delta progress), list name length 1024,
Error.message length 200, Summary.top count 5, identifiers, snapshot chunks,
frame bytes and per-subscription revisions. SubscribeArgs exposes
`effective_interval_ms(default)`: raw wire input is retained, effective values
clamp to 250..10000, and the default is supplied by the topic/client context.
since_seq requires the events topic. Boundary tests use values below, at and
above the declared bounds, including Unicode character lengths, overflow and
non-finite progress.

The round-trip checker returns file/1-based-line diagnostics and rejects frames
that serialize losslessly but violate those rules. Revisions are checked on
every subscription frame. An unsubscribe request preserves the old counter
until its success reply; the in-flight-frame regression checks both valid
continuation and an invalid reset before acknowledgement. The gap fixture must produce exactly the one
sub=1/rev=5 mismatch after accepted rev=3, preserve the prior revision, then
unsubscribe/re-subscribe and rebuild. Other validation is still applied before
that expected mismatch. Typed success and mutation-result comparisons, unknown
argument rejection, canonical sorted JSON, sentinel pointers and fixture-backed
documentation examples retain their original checks.
