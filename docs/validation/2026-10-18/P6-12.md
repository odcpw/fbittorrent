### Initial implementation

The fork already suppresses private-torrent DHT discovery and outgoing PeX.
The new native `private_no_dht_no_pex` test exercises those guards through
`Session::add_torrent`, with real HTTP tracker, UDP DHT and TCP peer fixtures.
All advertised remote addresses are loopback addresses; persistence is off,
storage is temporary, and no owner torrent, daemon or desktop service is used.
LSD multicast is disabled only in this test fixture; LSD is outside this
test's observed criteria.

The regression found a related tracker leak: `make_peer_rx` appended the
session's extra trackers when private metainfo contained one tracker or none.
The private branch now always excludes session trackers. Public torrents keep
their extra trackers and DHT/PeX discovery. This implements the relevant
[BEP 27 private-tracker restriction](https://www.bittorrent.org/beps/bep_0027.html).
The production change is confined to the vendored session's tracker-selection
branch; `src/engine.rs`, `src/network_app.rs` and `src/main.rs` are untouched.

The wire peer negotiates PeX extension ID 42 and remains connected for at least
12 seconds, beyond the engine's real 10-second initial PeX delay. The test
allows up to 25 seconds for the public control under load. The public torrent
must emit both DHT queries/announcements and a valid PeX frame; the private
torrent must remain connected and emit neither. A private torrent with no
metainfo tracker additionally verifies that session trackers are not used as
a fallback. Session stop, zero leaked obligations and worker shutdown are
checked before the protocol assertions.

### Independent review fixes

The orchestrator brought the initial-peer and tracker-order follow-ups back
into this bead, added per-add tracker injection coverage, and kept only the UI
criterion in the follow-on bead. This supersedes the initial follow-up list.

Private metadata now clears both caller-provided initial peers and peers seen
during magnet metadata resolution. Those merged metadata-discovery results
carry no tracker provenance. The private managed stream also suppresses
initial peers, DHT and LSD; received PeX remains ignored. Fresh peers returned
by the selected private tracker authorize outgoing connections for that run.
Both untrusted live-peer insertion and the outgoing queue check this
authorization, including reconnects from incoming peers' advertised ports.
Restarting discards the authorization and obtains fresh tracker responses.
Incoming connections are not made into authorized outgoing targets merely by
completing a handshake. This applies the outgoing-connection restriction in
[BEP 27](https://www.bittorrent.org/beps/bep_0027.html).

Per-add `opts.trackers` is ignored for private metainfo, including metainfo
with no tracker. Session trackers remain excluded. Public torrents retain
both kinds of tracker additions and initial-peer connections. The managed
tracker collection is now a Vec in metainfo order. `iter_announce()` already
uses announce-list tier order and gives it precedence over legacy announce;
private first-tracker selection now runs before conversion to a set. The
test verifies first-tier selection from two healthy tiers, as required by
[BEP 12 tier priority](https://www.bittorrent.org/beps/bep_0012.html).
Full tracker failover remains deferred, as allowed in the review request.

All production changes remain inside the vendored add/discovery and private
peer-admission paths. No `src/engine.rs`, `src/network_app.rs`, `src/main.rs`,
UI, tracker database or lifecycle refactor files were changed.
