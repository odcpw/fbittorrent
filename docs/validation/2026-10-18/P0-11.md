## P0-11 — Truthful peer labels

Bead `fbt-p0-11-tjs`, branch `ntm/fbittorrent/cod_4`. This is a source
checkpoint; P0-15 integration, process captures and the final gate are pending.

The native torrent details label now says `N peers connected`, using the
native engine's total in `num_leechs`. Legacy mode sums its connected seeds
and leechers for the same label. The widget no longer appends a fabricated
`Ns` seed count. Contract 1.1.1 adds the exact field note
`always 0 in native mode: unknown` for `list[].num_seeds`, explains
`num_leechs`, and records the clarification in `changes[]`. The numeric legacy
torrent fields are unchanged.

YTS deserialization now retains missing/null counts as `None`. Mapping into
the existing Nova-compatible `SearchResult` uses its existing `-1` unknown
representation; the TUI omits those values in rows and details. Actual zero
and positive counts supplied by a provider remain visible. This does not
introduce the future API's optional `seeds` field or change engine accounting.

The five wide goldens deliberately update the peer label and the native
render fixture now uses `num_seeds=0`. Four show the complete label; the fifth
is the exposed tail behind the wide help modal. Original plan/review captures
are preserved. No golden was regenerated wholesale.
