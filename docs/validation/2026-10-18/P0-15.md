### Changes

- `regression_tests/fbtlog.py` provides `Case`, timed step handles, optional
  assertion observations, `Case.popen`, per-case stderr slices, failure tails,
  suite summaries, forced failures and verbose JSONL output. Paths resolve from
  the module's repository, independently of the current directory. Each suite
  clears its previous logs on first use in a process.
- `regression_tests/native.py` converts the existing 11 scenarios to named
  cases, logs CLI results and asserted pane captures, and preserves all 49
  original application assertion conditions. Failed checks continue; unexpected
  exceptions produce a failed final record and let subsequent cases run.
  Every CLI result and failed pane capture is recorded immediately, including
  inside `wait_for`. Only successful intermediate pane captures are omitted by
  default, retaining the final asserted observation; verbose mode includes
  those intermediate captures and mirrors each JSONL line.
- `plugin/tests/qs-log.py` converts decorated `FBTQS-*` markers from merged
  process output, passes `NO_COLOR=1`, and includes the three-marker self-test.
- `scripts/testlog-summary.py` counts JSONL case verdicts, rejects failed
  intermediate steps even under a green final verdict, and reports the slowest
  five cases per suite. `all.sh` runs the logger and converter tests and invokes
  the summary last, including on earlier gate failures. It clears the four
  scheduled suites before any test/build stage, summarizes only those suites,
  and labels missing current logs as `not run`. Archived bead evidence is kept.
  Its background-panic scan remains enabled.

Here `regression_tests/` means
`agent_ergonomics_audit/audit/regression_tests/`.

### Tmux relaunch race correction

The orchestrator's 13:49 UTC gate on `b77f168` failed in
`quit_restart_down`: the socket was already removed, but the old tmux session
still occupied the name when `new-session` ran. That native suite is preserved
in `target/test-logs/fbt-p0-15-3hq/tmux-race-orchestrator-native/`.

Both launch sites now use `NativeHarness.start_tmux`. Before starting a
session it polls the private server's `has-session -t <name>` for up to ten
seconds, with each subprocess bounded by the remaining budget. One JSONL step
records the session name, elapsed time, probe count, last exit code and stderr.
If disappearance is not confirmed, the step fails and `TimeoutError` prevents
the relaunch. The private server uses `exit-empty off` between sessions so
session disappearance cannot race the server's own shutdown; the existing
fixture cleanup still kills that server. The only cod_2 ideas used were the
session-absence wait and keeping the private server alive. No P0-10 cases or
application assertions were copied or changed.

The new `tmux_relaunch` logger regression uses real tmux processes. It first
reproduces `duplicate session` by reusing a live session's name. It releases
that session only after two positive `has-session` probes, then verifies the
replacement starts after an absent result. A second fixture keeps its session
alive with a shortened 0.2-second test budget and checks the failed JSONL step,
clear `still present` / `exit 0` observation and absence of the replacement's
sentinel file. This tests the timeout without spending ten seconds per gate.

### Settings reopen readiness correction

The orchestrator's 14:06 UTC gate on `a1caafd` reached a closed status with no
`connection` field. The old `connection != "vpn_waiting"` predicate accepted
that response, then `show` exited 4 and indexing `state` raised `KeyError`.
That suite is preserved in
`target/test-logs/fbt-p0-15-3hq/reopen-race-orchestrator-native/`.

`wait_for_reopen` now requires status exit 0 with `ok=true`, `app_open=true`
and `connection=connected`, a present socket, and `show <hash>` exit 0 with
`ok=true` while the socket remains present. Status and show subprocesses share
the original ten-second readiness deadline, including process startup time.
The final wait step records the actual socket, status and show observations.
Its successful show response is reused for the manual-pause assertion instead
of making a second racy query. On timeout the wait fails and returns an empty
response so the pause assertion fails through `case.check`.

`cli_result` exposes both exit status and parsed JSON while `cli` retains its
existing return shape. Only readiness probes explicitly expect exit 0 or 4:
4 means still reopening, is logged immediately and never satisfies readiness.
Other exits, and exit 4 outside these probes, still fail the CLI step. The
settings case's CLI field accesses use `.get`, preserving their required
values while making an error response fail an assertion instead of raising
`KeyError`. All 49 assertion labels and required values remain; 44 condition
ASTs are identical and the other five differ only by guarded access or reuse
of the successful show response. No application source or P0-10 cases changed.

### Execution details and follow-ups

`--case` replays prerequisite scenarios in the disposable shared fixture and
logs only the selected case; this is documented in `--help`. The native suite
uses isolated config, data, runtime, state and cache directories and a private
tmux server/session named for this bead. Literal keys use `tmux send-keys -l`.

The first remote umbrella attempt hit Unix-socket `SUN_LEN` errors in three
existing unit tests because the worker's TMPDIR was too long. `all.sh` now uses
a host-target runner setting `TMPDIR=/tmp` for test execution, retaining the
normal Cargo shim. The next remote unit run passed all 104 tests. The release
build then hit rch's 300-second build limit; `all.sh` now defaults its build
allowance to 1,200 seconds while honoring an explicit override. These failures
are retained as `all-remote-tempdir-failure.log` and `all-release-timeout.log`
under the bead's log directory.

The worker subsequently built the release successfully in 6m16s, but its local
artifact-delivery process was terminated with exit 143. The cause of that signal
was not established. The retry reported an unfinished overlapping source owner
and selected rch's permitted local fallback. That fallback built the worktree
release successfully in 12m22s, and the final normal and forced umbrellas both
ran successfully to their expected exits using the local fallback. Logs:
`all-artifact-termination.log`, `release-delivery-retry.log`, `all-normal.log`
and `all-forced.log` under the bead's log directory.

Follow-up for the orchestrator: investigate the worker's interrupted artifact
delivery / unfinished source ownership or missing registry/target files if
they recur. No shared worker state was changed. Main/CI verification and bead
closure remain with the orchestrator.
