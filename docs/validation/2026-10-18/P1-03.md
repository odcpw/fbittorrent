## P1-03 — Daemon core: fbittorrent serve

Bead: `fbt-p1-03-ghy`. Branch: `ntm/fbittorrent/cod_1`.

The foreground `serve` entry point runs before search/TUI initialization. It
validates the private runtime directory, retries the stable instance lock for
five seconds, masks shutdown signals before spawning threads, ignores SIGPIPE,
and installs its own signal consumer and panic hook. The daemon owns the
listener, lifecycle and lock across replaceable engine slots. Its initial
`READY=1` datagram precedes session creation and all background hash checks.
The slot tracks starting/running/parked/stopping and a process-local epoch;
the process identity is 16 bytes from `/dev/urandom`, encoded as 32 lowercase
hex characters. The metadata needed by the future API server is available
through `Daemon::info()`; no API v1 operation or capability is introduced here.

The supervisor handles lifecycle requests and checks a configured interface
once per second. Engine restarts retain the listener inode, process identity
and lock. Missing interfaces serve the existing saved-history/intent routes
without a session. Daemon diagnostics name the configured interface; successful
ledger JSON passes through unchanged. The TUI compatibility path and its
existing route behavior remain available while P1-15 moves attachment.

Shutdown quiesces the persistent listener, cancels live dispatch before waiting
for the slot writer, drains the engine/runtime, joins transport workers, unlinks
the socket and releases the lock. An incomplete frame cannot extend shutdown
to the normal read timeout, and a request already read retains its reply.
Canceled engine operations return the legacy typed backend error with
`engine_unavailable` and the stopping/starting state. Panic exits 70 after
cleanup; ordinary signal shutdown exits 0. sd_notify supports pathname and Linux
abstract sockets, bounds datagram writes, and remains enabled with `--no-notify`.

The engine integration is confined to `engine/mod.rs` and its direct-construction
test helper: a shared instance-lock handle and `start_with_lock`, plus dispatch
quiescing. `ipc.rs` supplies bounded lock retry and preserves already-read
replies. `agent.rs` advertises `serve` and marks exits 70/75 as unit-only,
outside the CLI 0–8 dictionary. The P1-19 operation/view/ledger modules and
`network_app.rs` are not changed.

Every process case uses the shared JSONL harness, all five private XDG paths,
private recording shims and owned children/transient units. The old TUI probe
uses a private tmux server and `fbt-fbt-p1-03-ghy` session. Namespace mutations
run only after `unshare -Urn`, with a check against the parent's network namespace.
No installed fbittorrent service, owner torrent, live VPN or desktop UI is used.
