### Review correction: selected-piece completion

Dormant `size` and `completed_bytes` now come from the saved selection and
validated `.torrent` piece ranges. The calculation matches librqbit's
`compute_selected_pieces` and `HaveNeededSelected::{total,progress}` for a
completed selection: union the selected non-padding file ranges, count shared
pieces once, and use the actual final-piece length. It reads saved metainfo
only; it does not open or stat payload files or create session handles.

The new `dormant_restart_preserves_selected_piece_totals` test first checks real
multi-file data through librqbit, persists completion and `[0,1,4]` selection,
deletes an unselected 32,768-byte file, then restarts through `start_in`. The
57,347-byte torrent has 20,480 selected file bytes covering **24,579 selected
piece bytes** (shared boundaries plus an 8,195-byte final piece). Both checked
and dormant views must report 24,579 for size and completed bytes; the skipped
32,768 bytes remain unclaimed and absent. Saved file priorities and unknown
verification flags are retained. Metadata-only assertions also cover absent
and empty selections, overlapping ranges, the last piece and a zero-length
file. The legacy view is checked against the same corrected totals.
