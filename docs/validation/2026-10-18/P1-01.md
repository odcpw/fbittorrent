## P1-01 — A lifecycle object replaces the process-global statics

Bead: `fbt-p1-01-9ts`. Branch: `ntm/fbittorrent/cod_2`.

`src/daemon/mod.rs` declares only `pub mod lifecycle;`. The new `Lifecycle`
shares an `Arc<(Mutex<State>, Condvar)>` across the engine dispatcher, parked
engine controls, TUI and outer application loop. It owns pending stop/restart
requests and the expected network snapshot. The four old globals
`QUIT_REQUESTED`, `RESTART`, `CLOSE` and `EXPECTED` are removed.

Stop supersedes unhandled restarts and preserves the first pending stop reason.
Other pending requests are delivered in FIFO order. A restart already received
by the owner can be followed by a stop; the required test prints
`[Restart(Settings), Stop(Idle)]`. The TUI observes a request without consuming
it; after teardown the outer owner consumes it and decides whether to reopen.
Settings, network transitions and explicit restart controls retain their distinct
reasons. `StopReason::exit_code()` maps normal reasons to 0, Panic to 70 and
Upgrade to 75, with unit coverage. The future daemon's signal/panic/idle/upgrade
consumers are outside this change; the current terminal signal teardown remains
in place.

The new `engine::tests::two_engines_one_process` uses the production startup
path with explicit private directories and local-only session options. It opens
two actual engine IPC sockets, prints both directories and socket paths, checks
that starting the second engine leaves the first engine's request intact, sends
requests through both sockets, exercises both shutdown routing paths, and
verifies that dropping the first engine removes only its socket while the second
continues to answer. Additional tests cover parked shutdown, independent network
expectations, TUI observation/quit, request precedence, FIFO delivery, wakeup,
timeout and stop exit codes.
