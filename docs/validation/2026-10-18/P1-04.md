# P1-04 — static systemd user unit and start on demand

Bead: `fbt-p1-04-sf7`. Branch: `ntm/fbittorrent/cod_1`. Base: `fc0e33f`.

Native setup now writes the selected static user unit with the current executable
path and reloads the manager. It does not enable or start the service. The unit
uses Type=notify, NotifyAccess=main, KillMode=mixed, a 20-second stop timeout,
on-failure restart with two-second delay, exit-75 restart/success handling,
NoNewPrivileges and a 20-start/60-second limit. It has no Install section.
`setup --uninstall` removes the selected unit and keeps saved data. The
FBITTORRENT_UNIT override is shared by setup and startup; invalid names,
including non-UTF-8 values, are rejected rather than falling back to the owner
unit.

`src/api/client.rs` provides a 200-ms Unix-socket connect/framed-version probe,
bounded systemctl calls, a two-round start policy and the deactivating-unit
retry. Without a manager/installed unit it returns backend/4 with the foreground
serve hint. Failed starts return backend/4 with the selected unit's journal
command. Control commands use the real user's systemd transport; this override
is scoped to systemctl, never the daemon's runtime/config/data paths. The probe
uses the existing framed engine.sock protocol until P1-11 installs API hello.

Native writes now use that helper through backend::ensure_running. Reads,
status, stop and delete-keeping-files never start an owner; offline ledger
mutation itself remains P1-11. Invocation policy is kept outside Config so it
cannot persist autostart=false accidentally. Explicit up/dashboard override the
stored autostart setting, while the invocation-level no-start flag remains
binding (including direct serve). Up starts only the owner; --ui and dashboard
perform explicit UI dispatch. Dashboard passes one JSON argument to the shell
panel or requests the TUI launcher when the panel/shell is absent. Restart
currently requests an engine-slot restart, with process upgrade work left to
P1-17. Down sends the owner shutdown control without first waiting for an engine
version and waits for lock release, returning timeout/8 on its deadline.

Desktop handlers are written under XDG_DATA_HOME/applications. The ordinary
entry invokes dashboard, while the magnet entry remains a direct add %u with
Terminal=false. The source installer builds with --release --locked, serializes
replacement/setup, copies to fbittorrent.tmp and renames over the installed
binary before setup --magnet. Documentation and command capabilities describe
the new behavior; contract version remains 1.1.1. No API v1 operation or key was
added. Main's inline api module initializer avoids writing P1-06's api/mod.rs.
The full TUI quit/attachment changes remain P1-15; main's existing-owner TUI
route permits the explicit dashboard fallback to attach without relaunching.

## Development observations and isolation failure

Evidence root: `target/test-logs/fbt-p1-04-sf7/`. Initial compilation caught an
escaping typo in the unit renderer (`development/p104_check/`, exit 101), fixed
before any unit launch. Subsequent debug unit runs passed 197 application tests
with one existing subprocess-probe ignore. `development/p104_check_final/` and
`development/p104_test_final/` both exited 0 with clean worker-failure scans.
The final gate also qualifies the later CLI-help, strict unit-name and direct
serve no-start changes. Python and shell syntax checks passed in
`development/p104_syntax/` and `development/p104_shell/`.

The first static-unit fixture accidentally retained Sandbox's systemctl refusal
shim, causing setup failures. In the subsequent batch, a missing PID reached
`os.kill(0, SIGKILL)`, killing the test runner (exit 137). That is a harness error,
not an infrastructure failure. The disposable unit/link left by that interruption
was stopped/unlinked and its exact temporary tree removed. Signal cases now
require PID > 1 and a match with the owned socket's SO_PEERCRED PID before any
signal; the stopped-process race also resumes its owned PID in a finally block.

**The next systemd batch violated the required test isolation.** Drop-ins beside
externally linked unit files were not loaded by the manager. Six disposable
unit names briefly ran native sessions in the manager's default environment,
instead of the intended private XDG environment. This is not credited as valid
acceptance evidence. `isolation-incident.json` records journal counts (one ready,
session-start and socket-unlink sequence for each of those six units) and the
post-cleanup state: every involved unit was not-found/inactive with MainPID=0.
The affected names and failed cases are retained in `debug-fixed-systemd/`.
Live torrent-state effects are **unverified**; this receipt does not claim the
owner's data remained unchanged, and no rollback of live state was attempted.

The corrected fixture installs only uniquely named links/drop-ins in the real
manager's runtime lookup directory. Before any start, it checks the manager's
loaded DropInPaths, every private environment field and WorkingDirectory;
failure aborts the case and cleans the fixture. After CLI operations it checks
the actual owned child's selected environment fields and working directory.
A further cwd check exposed invalid quoting of WorkingDirectory; the corrected
raw absolute fixture path passes both checks (`isolated-down-fixed.*`). Cleanup
stops only the selected test unit, removes its links/drop-ins, reloads, and keeps
recorded control/launcher argv in per-case artifacts.

The early HTTP-only magnet fixture timed out because rqbit ignores xs= sources.
A second real isolated engine supplied a local seed, but the private metainfo
still timed out: P6-12 deliberately refuses BEP 9 metadata exchange for private
torrents. The corrected fixture uses non-private metainfo, two engines bound to
lo, and only loopback trackers/peers. It verifies the seed's complete payload and
real peer handshake, then resolves the magnet via that peer. It passed in
`magnet-local.*` (1.932 seconds); no vendor/engine behavior was changed.
The deterministic deactivation fixture also caught a wrapper syntax error;
its corrected real-manager interleaving passed in
`debug-local-start_while_deactivating/` (3.200 seconds).

The remaining final evidence and acceptance rows below use only the guarded
fixtures. Dashboard/MIME shims qualify command arguments and generated files;
they are not live desktop-window proof. Installer qualification uses the real
build/install/setup script under the same release lock and memory scope as the
gate, with an owned running daemon and an executable path containing spaces,
percent and dollar characters.

An additional real executable-path regression then exposed a unit renderer bug:
systemd interpreted `$$` literally in the executable word. The retained journal
observation in `exec-path-copy` identifies an attempted path with two dollar
characters. The renderer now retains a single literal dollar, while escaping
percent specifiers. Its unit assertion was corrected, and the full Rust suite
was rerun: **197 passed, one existing ignore**, with clean worker scan in
`development/p104_literal_tests/`. This is the only production-code delta after
the green all.sh run; no second all.sh invocation was made. The final binary and
all affected real systemd/installer cases were requalified below.

The first installer case was separately rejected before launch by the new
isolation guard: systemctl's displayed Environment escapes a dollar inside a
quoted value, and Python shlex retains that display escape. The fixture now
normalizes that representation and independently checks the actual child's raw
/proc environment afterward. `install-atomic/` and `install-atomic.result.json`
retain this expected-unusable first run, so `wrapped-gate.exit=1` describes the
combined gate/installer runner; it does not replace the successful all.sh result.
