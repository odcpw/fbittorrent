## P1-06 — API v1 server

Bead: `fbt-p1-06-tt1`. Branch: `ntm/fbittorrent/cod_2-p1-06-tt1`.

**Not merge-ready.** The implementation and regression gate below pass, but
strict live replay of the frozen transcripts does not. Subscription routing also
needs the P1-08 scope ruling described below. Neither is credited as complete.

The daemon now owns api.sock beside engine.sock, with the same instance lock,
0700 runtime directory and 0600 socket permissions. SO_PEERCRED enforces the
owner uid. The listener and established connections survive engine replacement;
the daemon retains slot, lock, signal, panic and lifecycle ownership.

The transport has a five-second accept-based hello deadline, recursive duplicate
key detection, strict typed requests, 64 KiB input and 1 MiB output bounds,
32 connections, eight in-flight IDs per connection, eight dispatch workers and
a 64-job queue. Every connection has a reader, writer and bounded 512-frame
outbox. Default/add deadlines are 15/95 seconds; generation checks discard late
results without affecting a reused ID. Owner shutdown/restart remain responsive
when dispatch is saturated. Draining resolves accepted requests or rejects them
as stopping, completes pending URL outcomes, sends bye last and joins threads.

The operations use typed EngineOp execution. Internal additive results carry
atomic add hash/duplicate outcomes and full torrent metadata. File selection is
admitted with the add, unresolved magnets return their durable hash without
waiting for metadata, and URL adds return pending followed by mutation.result.
References are correlated but have no replay/deduplication cache; that remains
P1-09. app.client flags are held per connection and reset on disconnect.
Only torrents/files capabilities are advertised, as the bead specifies.

The event transport provides capability-checked, count/byte-bounded snapshot
and added-delta senders for P1-08. Its Unix-stream unit test moves 1,100 items in
11 frames, maximum 1,042,565 bytes including newline, with every item preserved
and contiguous revisions 4..14. Live subscribe/unsubscribe routing and the event
bus are not implemented or advertised here; large list/files responses exceeding
the cap are refused, not emitted unbounded. Thus delivery of large collections
through a live subscription still requires the pending P1-08 scope ruling.

volatile paths, logs the exact first difference and stops before later absolute
fixture paths or example.invalid URLs can touch an unowned resource. The two
questions raised during implementation remain pending: how these scenarios are
to be replayed against a real server, and whether P1-06 should implement initial
subscriptions or provide the transport for P1-08. All 187 lines remain frozen.
