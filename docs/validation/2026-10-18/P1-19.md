## P1-19 — Typed operations and the normalized model

Bead: `fbt-p1-19-y2n`. Branch: `ntm/fbittorrent/cod_2`.

This receipt retains the initial validation history. The review correction below
supersedes the initial claims about compiler exhaustiveness and complete legacy
byte preservation in commit `9e60087`.

All 22 existing engine/control routes have one production server definition in
`src/engine/ops/parser.rs` (`LEGACY_ROUTES`). `EngineOp::parse(route, &Request)`
returns typed operation data or None for another feature's route. The engine,
parked ledger and network controls execute typed variants; their duplicate
string-route lists are removed. Client request strings and test fixtures remain
at their transport/test boundaries. No new CLI verb or external API operation
is added, and the existing CLI JSON contract keeps its shape.

Public engine interfaces for the dependent beads:

- `engine::ops::{EngineOp, EngineResult, HashSelection, AddRequest, Route,
  LEGACY_ROUTES}`; `EngineDispatcher::execute(op) -> Result<EngineResult>`.
- `engine::view::{TorrentView, TorrentState, Intent, UploadPolicy}`. Typed list
  results contain normalized views. `TorrentView::to_legacy_json()` is the only
  qBittorrent state-string conversion; `EngineResult::to_legacy_json()` preserves
  the existing legacy response forms.
- `EngineDispatcher::ledger_generation()` and `ParkedLedger::ledger_generation()`
  return `Arc<LedgerGeneration>` with `current()` and
  `wait_after(generation, timeout) -> Option<u64>`.
- `ParkedLedger::new(directory, lifecycle)` retains a generation handle across
  parked reads and mutations. The current parked server retains one such owner.

Typed operations cover reads, additions, start/stop/delete, file priorities,
upload/share policy, tags, queue settings, app controls and the existing
unsupported preference/toggle requests. Parsing performs legacy coercions;
execution also validates primitive arguments from direct typed callers before
mutating state. File addition works directly with file bytes and no URL field.
The existing metadata admission, durable intent, queue, cap, restore cancellation
and shutdown paths remain in use. Restore work moved without policy changes to
`src/engine/restore.rs` to keep the operation module below the size ceiling.

The normalized state derivation has explicit precedence: parked; error; active
verification; metadata; durable user pause; finished/no-seed policy; queued;
then live seeding/downloading/stalled or an inactive paused handle. A saved
pause does not hide active verification, and only a successfully drained check
is treated as cancelled. Reasons identify user pause, queue fullness,
completion suspension, VPN waiting and restore/metadata-timeout failures.

Unknown progress/size/counters, rates/peers when not live, zero-rate or
non-downloading ETA, zero-denominator ratio, unknown/nonpositive completion dates
and unavailable metadata paths are omitted from normalized JSON. Future fields
without current provenance (seeds, playable, origin, IMDb id, queue position)
are absent. List names are capped at 1,024 characters, preserving full names for
legacy clients. Upload policy is the closed default_cap/unlimited/custom enum;
intent is run/pause. Current staged/force flags are false; checked reflects
whether the live handle has finished initial verification.

`Ledger.generation` is a shared handle containing the single `AtomicU64` plus a
standard mutex/Condvar pair. Sharing the pair in an Arc lets the bus retain the
counter without borrowing the async ledger guard. Both live and parked ledger
saves increment once after the ledger rename and directory fsync succeed, then
notify waiters. Reads, cache writes and failed saves do not announce a committed
ledger change. The counter is skipped in serialized ledgers. Delete replacements
retain the same generation handle. `wait_after` checks the atomic predicate
under the notification mutex, preventing a missed wake; it never locks the
async records mutex.

### Review correction — exhaustive mapping and legacy bytes

variants and that passing typed structs directly to serde changed member order
in parked lists, queue responses and settings. Both findings are fixed here.
`derive_state` now explicitly matches every Activity and distinguishes active
checks from cancelled checks before applying pause/completion/queue policy.
The 768-row expectation table is unchanged. Queue/settings again serialize
through Value; the parked legacy facade restores Value ordering for its torrent
and file lists. Live list serialization is unchanged.
