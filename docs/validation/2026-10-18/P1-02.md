## P1-02 — Engine split (isomorphic)

Bead: `fbt-p1-02-thi`. Branch: `ntm/fbittorrent/cod_2`.

The former `src/engine.rs` is split into the plan's seven engine modules:
`mod.rs` (owner, startup, shutdown and shared types), `ledger.rs` (records and
fsync-backed writes), `queue.rs` (admission and limits), `ops.rs` (existing string
routes, additions and restore work), `view.rs` (existing torrent-list JSON and
state mapping), `parked.rs` (saved-history/intent dispatch), and
`legacy_import.rs` (engine import plus the capture/retirement orchestration moved
from `main.rs`). The existing public engine paths remain available. The entry
point in `main.rs` imports the relocated migration function.

Existing test bodies are included from smaller files into the same
`engine::tests` module; all existing libtest names remain unchanged. The main
migration store test also keeps its name. Visibility is widened only as needed
inside the engine or crate for moved code and the existing migration test.
The feature modules remain in their original locations.

Before moving production code, a new characterization fixture ran against the
monolithic engine and captured 2,704 bytes of `torrents/info` JSON into
`src/engine/tests/info-before-split.json`. It includes actual verified complete
and incomplete paused handles, plus controlled unit-fixture restore outcomes
for checking, metadata, stopped/unknown completion date and error. Only the
unique temporary root is replaced by `<FIXTURE>`; serialization order, fields
and all remaining bytes are compared exactly. The capture branch was removed
before the full pre-split test run. The permanent test cannot update the golden.
`info_json_identical_after_split` reports the first differing JSON pointer on
failure; a separate test checks array paths, missing keys and pointer escaping.

`944dee51130d18b9d7792c004512a7cb8c9676146ddb0d0db6a34ad7acbfe8b2`.

`move-audit.json` verifies all 116 original engine/main function bodies remain
