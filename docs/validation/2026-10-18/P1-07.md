### Implementation and positive checks

- `daemon.py` uses the P0-15 `Case` logger, deterministic `--list`/`--case`
  selection and mutually exclusive `--systemd`/`--no-systemd` modes. `FutureDaemon`
  contains the future command, socket and unit assumptions in one marked adapter.
  P1-06 owns the future `ApiConn`; it is not stubbed here.
- `Sandbox` creates HOME, TMPDIR, all five XDG paths, downloads and recording
  shims below one private, short `/tmp/fbt-d-*` directory. Config binds engine
  networking to loopback, disables autostart and notifications, and uses a
  disposable unit name. A fresh empty ratings TSV and negative title entries
  prevent unrelated IMDb fetches for these torrents.
- Foreground processes have their own process groups. Systemd mode creates
  transient, collected user units with names derived from the sandbox, explicit
  child environment and bounded stopping. No installed owner unit is used.
  Each child's stdout is separate; `Case.popen` retains stderr for the case's
  `<case>.daemon.log` slice.
- `notify_and_process` uses real Python children, AF_UNIX datagrams and, in
  systemd mode, real transient units. It verifies exact READY/STATUS delivery,
  all five XDG paths and the unit environment, a second independently named
  child with expected exit 7, stdout/stderr capture and reaping. Only the service
  child receives the fake `NOTIFY_SOCKET`; giving it to `systemd-run` too caused
  a real readiness-message collision, reproduced in
  `systemd-notify-before-fix/` and fixed before the passing runs.
- Shared fixtures include a 256 KiB random payload with private metadata,
  piece hashes, `.torrent`, loopback HTTP exact source and local empty-peer
  tracker; a two-file torrent starting its second file 123 bytes into a piece;
  byte corruption; a 64 MiB Matroska header carrying 120 s duration; and a
  non-video ISO-named payload. The Matroska body is random EBML Void data, not
  playable video; the ISO payload is not a mountable image. These fixtures
  support the future container-header and extension cases without claiming
  playback or the deferred seed/leech pair.
- The interim case adds both private torrent fixtures, stopped, through the
  actual CLI/socket/engine. It checks their exact info hashes, 256 KiB size and
  both multi-file lengths, then closes the app and waits for exit/socket removal.
  Its tmux server is private and its session is `fbt-fbt-p1-07-0h3`.
- `fixture_servers` exercises the real directory-backed loopback servers with
  checked-in EZTV, IMDb suggestion/poster and Torznab JSON recipes. It verifies
  response data, a local redirect, a redirect loop, missing files, traversal
  refusal and joined server threads. These are canned service inputs; provider
  integration belongs to its later items.
- `path_shims` checks literal argv boundaries and scripted stdout. Calls such
  as `fixtures.path_shim(name, script)`, `mkv_fixture(64 * MIB)` and
  `two_file_fixture()` use the active Sandbox; callers can also supply explicit
  directories.
