`ManagedProcess.close()` now cleans the owned transient unit and process group
independently of launcher status, reaps the launcher, checks for remaining live
group members, and verifies that the transient unit was collected. Successful
cleanup is idempotent. Systemd units explicitly use `KillMode=control-group`.
The launcher-first regression adopts/reaps its foreground orphan with a scoped
Linux child-subreaper setting and restores the prior setting. Its rescue path
also contained the expected pre-fix failures.

Systemd control calls preserve the parent's environment, including the real
runtime path used for implicit user-bus discovery. The fake `NOTIFY_SOCKET` is
removed from the controller environment so only the service sends test
notifications. The service receives explicit sandbox environment values and
`WorkingDirectory=<sandbox.root>`; its `XDG_RUNTIME_DIR` remains isolated.

`systemd_without_bus_address` is systemd-only. Default `--no-systemd` runs never
require user systemd; explicitly selecting that case without `--systemd` exits
2 instead of reporting an unexercised pass. `--list` enumerates all seven cases.

### Other implemented behavior

- `FutureDaemon` groups future command/socket/unit assumptions in one marked
  adapter. P1-06 owns the future `ApiConn`; it is not stubbed here.
- `Sandbox` owns HOME, TMPDIR, all five XDG paths, downloads, configuration,
  recording PATH shims and local IMDb cache entries below one private short
  directory. Engine networking is bound to loopback; autostart/notifications
  are disabled. Shims retain literal argv boundaries and scripted stdout.
- Shared payloads include a random 256 KiB private torrent with local HTTP
  exact source and empty-peer tracker, a two-file torrent whose second file
  starts 123 bytes into a piece, byte corruption, a 64 MiB Matroska header
  carrying a duration, and an ISO-named non-video payload. The Matroska body
  is random EBML Void data, not playable video; the ISO is not a mountable image.
- The interim case adds the single- and multi-file torrents, stopped, through
  the real CLI/socket/engine and checks hashes, size and both file lengths.
  It uses a private tmux server/session, then closes/reaps the app and checks
  socket removal. Every CLI result is logged immediately.
- Directory-backed loopback HTTP cases check canned EZTV, IMDb/poster and
  Torznab responses, redirects, redirect loops, missing/traversal paths and
  joined server threads. These are fixture inputs, not public-provider proof.
