## P0-09 — One bad record no longer blocks startup

Bead: `fbt-p0-09-kzw`. Worktree branch: `ntm/fbittorrent/cod_2`.

The engine returns after session creation and schedules independent restores,
with cached metadata tasks admitted before magnet-only tasks. Lists include all
ledger records while they restore: `checkingDL` for cached metadata, `metaDL`
for a resolving magnet, and `error` plus optional `error_message` after failure.
The in-memory `EngineDispatcher::restore_outcomes()` exposes each outcome,
including `restore_failed`, for P1-03. The existing metadata timeout stays 90 s.

Start retries a failed restore. Stop and removal cancel its resolution; a
removed or stopped generation cannot admit a stale handle. Restores use the
current saved intent when admitting metadata. Error messages reach the CLI's
show JSON/text and the TUI details column. Unchecked progress is described as
waiting for metadata or verification unless the engine is waiting for its VPN.

Only `src/engine.rs`, `src/qbt.rs`, `src/main.rs`, `src/tui/mod.rs`,
`agent_ergonomics_audit/audit/regression_tests/native.py` and this receipt change.
No tracker edits, live user data, installed binary, or installed widget changes.

All commands use
`CARGO_BUILD_JOBS=4` and the normal rch shim. The gate acquires the release lock
and enters the prescribed user systemd scope with MemoryHigh=10G and
MemoryMax=14G. Its five temporary XDG roots are applied *inside* the scope, after
connection to the real user bus. Legacy live-service and widget opt-ins are off.
