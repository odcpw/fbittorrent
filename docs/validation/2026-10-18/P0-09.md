## P0-09 — One bad record no longer blocks startup

Bead: `fbt-p0-09-kzw`. Worktree branch: `ntm/fbittorrent/cod_2`.

The engine returns after session creation and schedules independent restores,
with cached metadata tasks admitted before magnet-only tasks. Lists include all
ledger records while they restore: `checkingDL` for cached preflight or an active
hash check, `stoppedDL` for a paused/cancelled check, `metaDL` for a resolving
magnet, and `error` plus optional `error_message` after failure.
The in-memory `EngineDispatcher::restore_outcomes()` exposes each outcome,
including `restore_failed`, for P1-03. The existing metadata timeout stays 90 s.

Start retries a failed restore while retaining its last error until success or
a new failure. Stop and removal cancel its resolution; a
removed or stopped generation cannot admit a stale handle. Restores use the
current saved intent when admitting metadata. Error messages reach the CLI's
show JSON/text and the TUI details column. Unchecked progress is described as
waiting for metadata or verification unless the engine is waiting for its VPN.

Only `src/engine.rs`, `src/qbt.rs`, `src/main.rs`, `src/tui/mod.rs`,
`agent_ergonomics_audit/audit/regression_tests/native.py` and this receipt change.
No tracker edits, live user data, installed binary, or installed widget changes.

All commands use
`CARGO_BUILD_JOBS=4` and the normal rch shim. The gate acquires the release lock
and enters the prescribed user systemd scope with MemoryHigh=10G and
MemoryMax=14G. Its five temporary XDG roots are applied *inside* the scope, after
connection to the real user bus. Legacy live-service and widget opt-ins are off.

## Independent-review corrections

The original gate above predates independent review and is retained as history.
Review found a cancelled check incorrectly mapped to `checkingDL`, and retries
cleared their previous diagnostic before restoration succeeded. The correction
commit is `3717c76b01f5261dafe5a5e18a7a077a61415440`.

- `Initializing { paused: true }` now maps to `stoppedDL`; only an active
  initialization maps to `checkingDL`. A real sparse 1 GiB fixture is stopped
  after hashing starts, lists as stopped with durable paused intent, then resumes
  and verifies through the engine. A separate process case checks the actual
  Resume footer and invokes Resume with the TUI's `p` key.
- The last restore error is independent of the attempt's current state. Pending
  metadata/checking retries retain it; a new failure replaces it; a successful
  restore clears it. Both unit and process regressions exercise corruption,
  unresolved retry, a second failure with mismatched metainfo, and repair.
- The new process cases accept empty stderr or exactly one line matching
  `INFO engine drained in [0-9]+ ms` (with an optional final newline). Other
  lines, malformed durations, leading whitespace and extra blank lines fail.
  Positive and negative fixtures exercise the same predicate used on real
  process stderr. P0-08 itself has not been merged into this branch.
