## Production change and deterministic controls

The accepted teardown order remains: cancel restores, join their cleanup, stop
the session, close the runtime. The four-second production budget is unchanged.
`RestoreJoins` now owns the current and retired handles while awaiting them. Its
Drop implementation returns current handles to the matching generation and
returns unfinished superseded attempts to the retired list. This runs on success,
error, cancellation and timeout. No bookkeeping lock spans an await. An unfinished
current restore therefore remains `Some(handle)` after a join timeout instead of
making the original post-drop `is_none_or(is_finished)` assertion vacuous.

The peerless magnet and real local UDP tracker remain. Each fixture observes the
resolver's actual 16-byte tracker connect request; the tracker never answers.
The cleanup epilogue now waits on an explicit cancellation-token notification.
A **test-only** hook releases it only after teardown has taken ownership of the
handles to join. If application-region cancellation wins, the epilogue or its
Drop guard records phase 3; otherwise the rendezvous completes under the live
application context and records phase 2. Ordering uses no sleep window.

The old-order negative control calls a test-only copy of the former production
sequence (cancel, session stop, runtime shutdown, without joining restores),
selected by `FBT_P103B_FORMER_ORDER`. This switch can only make the phase assertion
fail; it cannot bypass an assertion. Both corrected regressions failed at that
assertion in all 30 old-order runs each: native test exit 101, phase **3 instead
of 2**, with no unrelated worker error. The runner explicitly expects that
failure, records `expected_failure: true`, and retains each failing test output.

The new timeout control runs full `AppEngine::drain`, with a 50 ms fuse and a
250 ms wall-clock ceiling. After the real resolver joins, a test-owned channel
barrier blocks its cleanup worker until the test releases it. At teardown return,
the control observes all of:

- `drained=false`, with the production join-timeout error logged;
- current `task: Some`, `is_finished=false`;
- the **unchanged original completion predicate evaluates to false**.

It then releases its own worker and observes completion. The subprocess captures
expected engine errors so ordinary worker-failure scanning remains strict. Its
parent verifies success, the exact join-timeout diagnostic, and an allowlist of
only the three expected engine timeout lines. Any extra stderr line, panic or
unexpected outcome fails the test. Complete child output is transported as a
base64 marker and decoded by the local runner into the listed timeout artifacts;
it is not discarded. The parent watchdog's polling interval does not determine
teardown ordering.
