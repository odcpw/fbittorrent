# P1-03c — native-runtime deadline attribution

Bead: `fbt-50y`. Branch: `ntm/fbittorrent/cod_3-p1-03c`.
Baseline: `135493a` (includes the merged P1-03b corrections).
Evidence root (`L`): `target/test-logs/fbt-50y/`.

## Change and evidence boundary

Native runtime shutdown now emits an `ERROR engine` line for each failed phase,
with total elapsed milliseconds and a JSON snapshot of outstanding work. Region
close and runtime teardown failures accumulate in order in the returned error;
the second phase cannot replace the first. The engine's existing error logging
therefore receives both failures. NativeRuntime's fallback Drop logger also uses
the single-line engine format.

Snapshots traverse open descendant regions and identify active tasks by runtime
ID and owning region, state, phase, age, poll count, obligations and the last
checkpoint label when supplied. Root/application regions have explicit names.
Physical blocking work also has a separate `native_blocking_pool` observation
with busy-thread and pending-job counts, even after its async region has closed.
Serialization/logging happens after each runtime query releases its locks.

The observer retains state inspectors and a pool handle, never a Runtime or
strong RuntimeHandle. It can query after bounded runtime teardown without itself
keeping RuntimeInner alive. Snapshots are best-effort observations across
successive queries, not an atomic causal trace. The runtime API exposes neither
per-pool-job names nor strong runtime-owner counts; absent checkpoint labels are
null, and `runtime_ownership` explicitly says `not exposed by runtime API`.
The logger does not guess a storage, DNS, tracker or DHT cause for unnamed work.

The shared shutdown budget is unchanged; observer setup and region close use the
remaining budget, followed by runtime teardown with the remaining balance. No
engine lifecycle, restore decision, dormant path or restore-join implementation
changed. Production changes are confined to native runtime shutdown/diagnostics.

## Controlled regressions

Three subprocess controls exercise the actual native runtime, using channels to
establish and release the held state. The parent checks the exact phase count,
single-line `ERROR engine` format, JSON structure and attribution; extra stderr
fails. Complete child output is transported by a base64 marker and decoded into
the `*-timeout-1.log` artifacts, not discarded or treated as an unexamined pass.

- `blocked_storage_task_names_outstanding_work_and_preserves_both_failures` holds
  a task inside a grandchild region at a named storage-read checkpoint. Both
  deadline records must identify it and its age; the returned error must retain
  both phase failures. The task stays blocked until shutdown returns.
- `blocked_pool_is_attributed_after_application_region_closes` holds a physical
  pool closure after the application region successfully closes. Only runtime
  teardown fails; its record must name the pool and show one busy thread.
- `retained_runtime_owner_does_not_invent_region_failure` retains a real Runtime
  clone. Only runtime teardown fails; no active task or busy pool thread may be
  invented, and unavailable runtime-owner attribution is explicit.

Each uses a 50 ms shutdown fuse and an unchanged 250 ms wall-clock ceiling, then
releases its own work. This is local native-runtime evidence, not evidence about
the cause of an earlier uncontrolled production/test deadline.

The P1-03b join-timeout control retains every handle/completion/budget assertion.
Its stderr check is stronger: exactly five expected lines (two session errors,
both attributed native-runtime phase errors, and the combined error delivered
to AppEngine). Both snapshots must name `blocked_restore_cleanup`.

## Review correction — bounded diagnostics (fbt-50y, 2026-10-19)

This correction starts from `64bd004`, with the orchestrator's explicit scope
extension to `vendor/asupersync/src/observability/task_inspector.rs` and
`vendor/asupersync/FBITTORRENT_PATCH.md`. The original complete inspector queries
and all their callers retain their previous behavior. The additive bounded API
uses try-locks for runtime state, task and obligation shards, and checkpoint
contexts. It copies immutable region IDs/parents and atomic region state rather
than calling lock-taking RegionInner accessors. It avoids obligation and
checkpoint-history scans and unbounded cancellation-string formatting.

The API caps tasks, requested/owning regions and ancestors, encoded bytes,
checkpoint text, arena scanning (including vacant slots), and collection time.
Every omission/contended or poisoned lock is flagged in partial JSON. Application
limits are 16 tasks, 16 regions and 3072 encoded bytes, with a 5 ms collection
limit per attempt. A transient lock or preemption can trigger at most two
additional try-lock samples within 10 ms total; a richer partial observation is
retained if a later attempt has less information. Limits never turn a partial
observation into a quiescence receipt.

An observer thread starts during NativeRuntime construction. Its startup
rendezvous proves its Runtime clone has been dropped before the owner is
returned: it retains state and pool observations, not RuntimeInner. Shutdown
waits at most 20 ms for each observation, with a flagged one-line failure if the
worker is unavailable or late; no observer thread is joined on shutdown. Late
replies cannot emit duplicate/reordered deadline records. Both phase failures
continue to accumulate in the returned error regardless of diagnostic success.

A single process-wide output worker with one pending record opens a separate
nonblocking, append-only stderr file description, leaving stderr's own flags
and Rust stderr lock alone. Pipe writes are capped at PIPE_BUF; an unavailable
or oversized detail triggers a short failure-line attempt. The caller waits at
most 10 ms for output acknowledgment, including when a regular device stalls.
A completely full pipe cannot accept even a summary: details may be dropped,
but both one-line phase failures still reach the returned error. NativeRuntime
Drop and AppEngine's existing teardown error/info emissions use this same path.
Only logging in `AppEngine::drain` changed; restore joins, lifecycle ownership,
engine logic, transfer tests and the five-line timeout assertion did not.

The new saturated-stderr control fills a real blocking pipe, leaves it unread
until each child exits, and exercises both the original NativeRuntime worker
probe and the unchanged AppEngine join-timeout child. Their original 50 ms fuse
and 250 ms ceiling remain intact; no fake success/cleanup receipt is accepted.
The native child also verifies stderr flags remain unchanged and both returned
phase failures retain the checkpoint. The other new control creates 256 real
TaskRecords, holds an actual task CxInner write lock, and requires partial,
truncated JSON within its 5 ms cap and count/byte limits. Additional checks cover
zero bytes, an expired time cap, and independently binding task/region limits.
A vendored unit control additionally holds actual unified-state, task-table and
obligation-table locks in turn.

## Delta review correction — complete socket records (2026-10-19)

Baseline: `34b9cee`. This correction changes only native diagnostic output, its
shutdown tests, and this receipt. The bounded inspector, observer, lifecycle,
restore joins and transfer implementation are unchanged.

Socket output now tracks a byte offset, retries EAGAIN/EINTR with nonblocking
sends, and stops at a 5 ms output-worker deadline. The caller retains its separate
10 ms acknowledgment fuse. A short byte count is no longer a success receipt;
`emit` acknowledges a complete chosen record only. Both phase errors continue to
return independently of this status.

Fallback selection happens before sending the first detail byte: a stream cannot
retract an already committed prefix. The admitted record is capped by the
Linux AF_UNIX per-skb payload ceiling from SO_SNDBUF, additionally capped at
PIPE_BUF. A small send buffer therefore selects the complete fallback rather
than starting a detail that needs a second skb. The implementation follows the
[Linux AF_UNIX send path](https://raw.githubusercontent.com/torvalds/linux/master/net/unix/af_unix.c)
(`unix_stream_sendmsg`, sndbuf/2 minus 64). No socket flags or buffer settings are
changed in production. Once a record starts, offset retries continue that same
record; no fallback is spliced onto its prefix.

The existing socket test now also sets SO_SNDBUF=1024, queues one byte and leaves
the peer unread until the child exits. It replays a 2562-byte AppEngine-format
record containing the actual, asserted two-phase NativeRuntime error. Trailing
whitespace after the quoted error fixes the replay length without changing the
error. The child retains the original 50 ms shutdown fuse, 250 ms ceiling and
both returned-error/checkpoint assertions. The parent accepts only the exact
full record or exact complete fallback line, checks its final newline and one
record, and retains both child stdout and socket output. A separate real-socket
control reproduces a short send, exercises the zero-progress retry fuse, drains
the peer, resumes at the saved offset and compares the entire resulting record
byte-for-byte. The existing probe only gains a return value for replay; every
original assertion is unchanged.
